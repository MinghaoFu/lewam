# CLAUDE.md — LeWAM

## Standing rules for this repo

1. **Edit docs here; code + experiments live on L40S `le-wm-repro`** (the workspace, user 2026-06-22). This worktree has no runnable code. Train/eval on L40S (`sudo -u minghao.fu`, venv `lewm`); datasets + checkpoints under `/mnt/minghao_data`, disk-safe redirects per rule 10.
2. **The model is ONE class — `JEPA` in `le-wm-repro/jepa.py`**: CLS-token `encode`→latent z; `predict` = the FDM (z_≤t,a→ẑ_{t+1}); `predict_intention` = the action head / IDM (z_≤t,a_<t[,z_goal,horizon]→intention→`action_decoder`→raw action); `action_encoder`; `intention_rollout` = the actor (rolls FDM + head jointly). (The deleted local two-class `models/mt_world_model.py` was tcwm, a different lineage.)
3. **The loss is `lejepa_forward` in `le-wm-repro/train.py`**: `pred_loss + λ·sigreg_loss` (the LeWM base) plus config-gated `intent_loss` (predict act_emb), `act_loss` (raw action), `w_cyc` (FDM↔IDM consistency), goal-conditioned + AdaLN horizon, `sigreg_act`, proprio, InfoNCE align. Config: `config/train/lewm.yaml`. (The deleted local `conf/method/mtjepa.yaml` was tcwm.)
4. **Task conditioning is frozen CLIP.** Embeddings live in `*_tasks.json`. If you change task names/order, re-run `create_task_embeddings.py` AND update the matching `_TASK_REGISTRY` in `datasets/multitask_robomimic_dset.py` if a new task type is added.
5. **Action masks are auto-built from `action_dims` kwarg** passed by the trainer; padded action dims are zeroed before the action encoder and the consistency loss is per-sample-weighted by valid fraction.
6. Don't commit `wandb/`, `logs/`, `*.pt`, `*.png` outputs back into this repo.
7. **Maintain `EXPERIMENTS.md` — single source of truth for every experiment, AS DETAILED AS POSSIBLE.** Each entry records **motivation (why) → the EXACT full config (the literal launch command, every flag/hyperparam: `detach_decoder`, `w_act`/`w_intent`, `head`, `init_from`, `max_epochs`, `limit_train_batches`, `num_eval`, `eval_budget`, `goal_offset`, seeds, GPU) → result (ALL per-seed numbers, not just means) → conclusion.** Do NOT compress or summarize away settings — write the long version; tokens/context are not a constraint here (see rule 9). Update it **live**: when an experiment is launched, when results land, AND during chat/brainstorm as decisions/hypotheses are made (keep an OPEN QUESTIONS section). This exists because config drift silently invalidated results once (all robomimic ran `detach_decoder=false` while the validated design was `true`, because the flag never propagated from the PushT experiment to the launchers). Before trusting any number, check which exact config produced it here.
8. **No lazy / under-trained experiments — train to CONVERGENCE.** Per global rule 9, "full training" = performance plateaus (val loss / eval metric flat over the last ~10%); default proxy 100 epochs, extend if still improving ("when in doubt, train heavier"). The old 40-epoch×4000-batch GIP runs were under-trained — re-run headline arms at ≥100ep and verify the plateau before reporting any number. Never headline a 30–40ep diagnostic.
9. **Don't conserve tokens — use full context and long, detailed documents.** The user has ample budget and prefers thoroughness over brevity. Write expansive `EXPERIMENTS.md` / analysis docs, keep all settings and per-seed numbers, read full files rather than snippets when it helps. Terseness is only for the live chat status lines, not for the durable docs.
10. **USE AS MANY GPUs AS POSSIBLE (user, 2026-06-22) — every available GPU, co-locate MANY processes per GPU, never one-per-GPU, never leave a GPU idle.** le-wm models are small (~16–25 GB on 80 GB H100s), so pack several training/eval runs onto each GPU (auto-pick lowest-occupied via `nvidia-smi`); don't wait for a free GPU or leave GPUs underused. Run all the open arms in parallel rather than serially. **Reclaim YOUR OWN stale/orphaned runs to make room — but NEVER kill another user's processes, even stopped/old ones** (e.g. fan's 26-day `T`-state jobs holding GPU 3/6 memory): a stopped/idle process does no compute, so the GPU still has room — **CO-LOCATE on it, don't kill**. Only true zombies/orphans that are YOURS (`minghao.fu`, defunct or ppid=1 with no live parent) are kill candidates (via the host sudo user); other users' GPUs are off-limits (confirm with the user before any cross-user kill). Contention is acceptable; the real bottleneck is **disk/CPU**, not GPU memory — so when scaling concurrency keep the redirects (`TMPDIR`/`hydra.run.dir`/`HF_HUB_OFFLINE`/`MPLCONFIGDIR` AND **`SPT_CACHE_DIR`** — stable-pretraining writes its 855 MiB Lightning `.ckpt`/`metrics.csv` there and the other vars do NOT govern it; missing it caused disk-full crashes 2026-06-21, see EXPERIMENTS.md §infra) and `+ckpt_every=10` to avoid the disk-full crashes, and stagger launches (`sleep 7`) so the startup burst doesn't tip the disk.
11. **When an ablation/experiment FINISHES, update it into the unified table** (`results/gen_master_table.py` → regenerate `master_results.html`) — not just EXPERIMENTS.md. Fill the matching cell with the converged 3-seed N=50 number + its evidence entry. **If the experiment is a NEW setting (a regime/axis the current S1–S4 rows don't cover), OPEN A NEW ROW** (a new method-subrow under the right setting, or a new setting block) rather than forcing it into an existing cell. The unified table is the single at-a-glance source of truth; every finished ablation must be visible there, with `–` only for genuinely not-run cells. (Rule 7 keeps the long-form in EXPERIMENTS.md; this rule keeps the table in sync.)
12. **🚀 FAST-ADAPTATION STAGE (user, 2026-06-21): we are rapidly iterating the method/code toward the best results — this is NOT the final code.** So PRIORITIZE FAST EVALUATION over full-convergence rigor: train ablations only to a **REDUCED, PER-DATASET epoch budget** (near-convergence is enough to compare arms; different datasets converge at different rates, so customize — do NOT use a blanket 100ep). Reference: LeWM (the base) trains its envs for only **10 epochs** ("10 epochs sufficient to reach best performance"). **Default FAST-ITER budgets (verify the val_act plateau per dataset + adjust): pusht/cube/reacher ~15ep, two-room ~12ep, robomimic lift/can/square ~30ep, tool_hang/transport ~40ep.** EVAL at the fast budget and KILL the training once past it (free the box); don't let arms grind to 100ep. This OVERRIDES rule 8's "default 100ep proxy" FOR ITERATION ONLY — the **final HEADLINE numbers still get full convergence + 3-seed N=50** (rule 8 stands for the paper, not for the fast iteration loop). When in doubt during iteration, lean SHORTER (re-run longer is cheap once an arm looks promising). **⚠️ CONSISTENCY (mandatory for a VALID ablation): WITHIN one dataset, ALL arms of an ablation MUST share the SAME budget — same `max_epochs` AND same `limit_train_batches` (and same seed protocol) — only ACROSS datasets may the budget differ. A budget that varies between arms (e.g. the w_cyc sweep's 2000/4000/1000 batches) CONFOUNDS the ablation with training compute and is INVALID — match it or re-run. The per-dataset budget is chosen once (by the slowest-converging arm's plateau) and applied to every arm of that dataset.**
13. **🎯 END-TO-END IS THE BASELINE AND THE METHOD (user, 2026-06-22).** `freeze_wm=false` (encoder learnable end-to-end) is LeWAM — the goal, not an ablation arm. **EVERY ablation builds ON the end-to-end baseline**: take the end-to-end model and change exactly ONE component, keeping `freeze_wm=false` throughout. Examples: encoder = from-scratch vit-tiny (baseline) → pretrained DINOv2; sigreg on → off; w_cyc off → on; head mse → diffusion; goal_dropout, horizon, etc. **The frozen-latent regime (`freeze_wm=true`) is NOT the method and NOT a valid ablation arm** — it was a gcidm-matching control that mis-framed the GC campaign (§20/§27); do NOT report it as "ours" or compare arms across the frozen/learnable boundary. Report end-to-end numbers as the baseline and each ablation as a delta from it. The frozen-vs-learnable comparison is settled (end-to-end wins, e.g. pusht GC 31→~63) and is closed, not re-run.
